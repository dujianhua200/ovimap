# 滑洲云图 ovimap — 增量 PRD：DXF 导出底图矢量质量攻坚（v1.0）

> 类型：**增量 PRD**（只描述本次变更，不重写全量需求）
> 产出人：产品经理 许清楚　|　交付对象：架构师 / 团队主理人
> 定位：Android 单机 App（**个人自用**、可离线），面向通信线路外业勘察设计 + 竣工测量结算
> 技术底座：Flutter 3.x + flutter_map 8 + provider；DXF 走自研 `lib/export/dxf.dart`
> 本次主题：**让导出的 DXF 底图（道路 + 建筑 + 地名）像正规设计院出图那样美观、专业、信息完整**

---

## 0. 原始需求复述

> 导出的矢量都没有建筑轮廓，也没有小区名字，路线条太粗，路不美观，没有成熟的方案来解决这个问题，一定要解决，改了几十次一次都不满意。

用户身份：**通信线路设计人员兼竣工结算人员**。他要把 DXF 导进 CAD 做**设计图 / 竣工图**，**底图（周边道路 + 建筑 + 地名）是他判断杆位、写设计说明、给甲方看的必备参照**。

**真实诉求翻译**：不是要一张"能看"的图，而是要一张**像设计院出图那样——建筑成片可辨、道路分级清爽、地名齐全、杆路与底图主次分明**的图。用户要的是"**成熟方案**"，即不要再打补丁式微调，要一次性把制图规范性做对。

**本次迭代主题**：`底图可信 · 制图规范`。

## 1. 「满意」的可验收定义（QA 验收清单）

把用户模糊的"美观/不美观"翻译成**可逐条检验**的验收项。验收方式统一为：**导出 DXF → AutoCAD/浩辰/中望 CAD 打开 → 按下列条目逐条判定**。

| # | 验收项 | 可检验标准（判定为"通过"的条件） |
|---|---|---|
| A1 | **建筑轮廓成片可辨** | 密集城区中心随机取 3 处，建筑轮廓**连成可辨认的图形块**，不再是"一片灰色乱线"；建筑内部有浅色填充（或底色区分），与道路、空白背景三层分明 |
| A2 | **建筑可见性不随比例尺塌陷** | 按图签自动比例（如 1:2000 / 1:5000）出图时，建筑轮廓线在纸质/PDF 上**仍清晰可辨**（线宽/对比度足够），不因缩小而消失 |
| A3 | **道路有等级区分、粗细分明、不粘连** | 主干道 / 次干道 / 支路 / 小路 ≥3 个可见等级；相邻道路平行时**不糊成一整块**；主干道一眼能认出（有中心线或明显分级样式） |
| A4 | **道路"瘦"下来** | 道路不再是一条条"实心色带"；主干道在图上占宽合理（视觉上像"双线街道"而非"色块"），支路明显更细 |
| A5 | **小区 / 村庄 / 片区名可读** | 底图上出现**小区名、村庄名、片区/社区名**（如"××花园""××村"），字号可读、不乱码、不与线路/道路文字严重重叠 |
| A6 | **杆路与底图主次分明** | 杆路（GanLu）、配线（PeiXianTu）等**业务图层在底图之上、线宽可控**，一眼能分清"我的线路"和"周边参照"；业务图层不被底图压住 |
| A7 | **杆路线条粗细可控、不过粗** | 杆路线条观感清爽（不糊），线宽可预期；竣工红色描边模式下仍清晰可辨 |
| A8 | **图面整体不像"乱麻"** | 缩放到全图看：有留白、有层次、可辨识，能直接作为"给甲方看的参照图"而不需要再手工收拾 |
| A9 | **失败可见可解释** | 若联网抓底图失败，用户能**明确知道"底图没抓到 / 抓到一部分"**，而不是拿到一张"没有建筑轮廓"的图却不知道原因 |
| A10 | **中文不乱码、可用** | CAD 中文字正常（GBK/ANSI_936），图例、图签、地名均正常显示 |

> 建议 QA 用一个**验收样例**固化：选一段"城区 + 城郊"混合线路（含密集建筑、多个小区名、主干道与小路并存），一次导出后逐条打分。通过线：A1–A7、A9、A10 全过，A8 人工判定为"可接受"。

### 2.1 新增根因（主理人未列，架构师需一并处理）

| # | 新增根因 | 位置 / 证据 | 影响 |
|---|---|---|---|
| N1 | **小区内部道路被当"噪音"丢弃**——无名的 `service/path/footway/track` 等被直接 `continue` 丢弃 | `overpass.dart:35-38`（minor 集合含 `service`）与 `overpass.dart:56-57`（却又给 service 赋宽 3.0m，属**自相矛盾/死逻辑**） | 小区内部路网（多为无名 service）被砍掉，"小区没路、像空地"；也削弱了"小区"的空间可辨性 |
| N2 | **关系型建筑（multipolygon）几何被当单环处理** | `overpass.dart:74-86` 对 `relation["building"]` 的 `geometry` 直接当一条环取点 | 带内院的复杂建筑可能出**畸形轮廓 / 连片错线**，加剧"乱麻" |
| N3 | **坐标/单位无 Bug（排除项）** | 道路（`dxf.dart:305-309`）与建筑（`dxf.dart:364-368`）使用**同一** `baseLon/baseLat/scaleX/scaleY` 投影 | 建筑**不会**因坐标/单位跑到很远；"没建筑轮廓"是**数据源失败 + 无填充不可见**两因叠加，**不是坐标问题**（避免架构师走错方向） |
| N4 | **道路简化容差对小路偏大** | `dxf.dart:1037` `_roadSimplificationTolerance = 1.0`（米），Douglas-Peucker 应用于道路 | 1m 容差对主干道无碍，但会**抹掉小路的小弯**，小路显得更"假"；建筑未做简化（保留全部点，正确） |
| N5 | **比例尺与线宽叠加放大"粗"感** | `dxf.dart:515-524` `_pickScale` 以 A3 可打印宽 0.40m 估算 | 12m 宽主干道在 1:2000 下纸上宽 **6mm**（夸张的色带）；1:5000 下 2.4mm。是"路太粗"的放大因素 |
| N6 | **建筑名注记偏小、字号硬编码** | `dxf.dart:382-387` 建筑名 `3.0m` 字高、按"字数×3.0×0.9"粗估居中 | 1:2000 下仅 1.5mm，偏小；且**只有建筑带 `name` 才标**（住宅楼多无名 → 无文字，符合"没有名字"的观感） |
| N7 | **天地图能力边界（重要）**：天地图仅提供**栅格瓦片**（`vec/cva/img/cia`）+ **地名/POI 检索 API**，**不提供建筑轮廓/道路矢量面下载** | `map_source.dart:154-183`（WMTS 栅格）、`search.dart:52-99`（v2/search 仅返回 POI/行政区**点**） | **结论**：天地图**不能替代 OSM 提供建筑轮廓**；它只适合补**地名/小区名**与**兜底参照**。这直接决定"成熟方案"选型（见 §3） |

### 2.2 根因归因汇总（一句话）

> 用户看到的四个不满，本质是**两条独立问题的叠加**：
> ① **数据缺失**——底图源（境外 Overpass）国内不稳定 + **从未查询地名** → "没建筑轮廓、没小区名"；
> ② **制图不规范**——R12 无填充/无线宽控制 + 直接把"真实路宽"当线宽 + 无分级画法 → "路太粗、路不美、像乱麻"。
> 二者**必须同时解决**，只修一头用户仍不会满意（这正是"改几十次都不满意"的原因）。

## 3. 成熟方案选型（本次核心）

> 用户明确要"成熟方案"。以下为**方案对比 + 明确推荐**，供架构师直接落技术设计。

### 3.1 底图数据源可靠性

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| S1 继续 Overpass（多镜像 + 竞速 + 重试 + 失败可见） | 改动小；已有并行竞速基础（`overpass.dart:120-149`）；几何数据全 | 国内仍可能全部失败；**无兜底** | **保留为主源**，但必须补：① 增加**国内可达镜像**（如通过 CDN/代理的 Overpass 端点）② 失败**乐观降级为"用上一次成功缓存"** ③ 失败**明确可见** |
| S2 改用国内数据源（天地图 / 自建瓦片） | 国内快、稳 | **天地图只给栅格瓦片与 POI 点，给不了建筑/道路矢量面**（见 N7）；自建瓦片同为栅格 | **不可作为几何主源**；仅用于**地名/POI 兜底**（见 3.2） |
| S3 项目级底图缓存（一次抓取、多次复用、离线可出图） | 首次联网后**永不再依赖网络**；出图快、稳、可复现 | 需新增缓存模型与"缓存新鲜度"提示 | **强烈推荐**，作为可靠性核心 |
| S4 离线底图包 | 完全离线 | 数据死板、体量大、无地名更新 | **P2**，不阻塞本次 |

**推荐组合（S1 + S3 为主，S2 兜底标签）**：
1. **几何（建筑/道路）以 Overpass 为主源**，**多镜像竞速**（保留现机制）+ 增加国内可达端点；单镜 15s 超时不变。
2. **项目级底图缓存**：以**线路包围盒（量化网格）**为缓存键，抓取成功后**逐项目落盘**；下次同区域导出**直接复用（可离线）**，并提供"刷新底图"手动动作。
3. **失败可见**：抓取结果区分三态——**全部成功 / 部分成功（缺道路或缺建筑） / 全部失败**；失败时给出**中文可操作指引**（"底图未获取：网络不可达，已使用上次缓存 / 本次无底图"），而不是一句 toast。
4. **地名（小区/村庄/片区名）**：OSM `place=*` + `landuse=residential` 名称为主 → **天地图 POI/地名搜索（`v2/search`）为兜底补充**（key 已内置 `app_state.dart:251`）。

### 3.2 地名 / 小区名的成熟做法

| 方案 | 数据形态 | 适用 | 结论 |
|---|---|---|---|
| OSM `place=*`（suburb/neighbourhood/village/hamlet/town）+ `landuse=residential` 的 `name` | **点 / 面 + 名称** | 与建筑/道路**同源同坐标系**，零额外依赖 | **主方案**（P0，必做） |
| 天地图 POI/地名搜索（`v2/search`，`queryType=1`） | **点 + 名称** | OSM 缺名时补充；国内覆盖好 | **兜底补充**（P0/P1，可开关） |
| 天地图"行政区划" | 面/点 | 大片区名 | 可选（P1） |

**推荐**：**OSM 为主 + 天地图兜底**，地名输出到**独立图层 `DiMing`**，按级别分层注记（片区 > 小区/村）。落点规则：`place` 点直接用点坐标；`landuse=residential` 用具名地块的**几何中心**。

### 3.3 制图规范（"美观"的关键）

> 参照国内设计院 CAD 出图习惯，把"底图"与"业务图层"分开，底图**低饱和、细线、成片**；业务层**高对比、可控线宽**。

**（1）图层命名与颜色规范（建议）**

| 图层 | 内容 | 颜色建议 | 线型/处理 |
|---|---|---|---|
| `DiMing` | 小区/村庄/片区名（**新增**） | 3（绿）或真彩浅灰 | 仅文字 |
| `DaoLuBian` | 道路**双线描边 casing**（新增） | 250 浅灰 / 真彩 `#C8C8C8` | CONTINUOUS，按等级线宽 |
| `DaoLuZhong` | 道路**中心线**（新增） | 等级色（主干红/次干黄…） | CENTER 或实线 |
| `JianZhu` | 建筑轮廓 | 8→改**浅灰真彩 `#B0B0B0`** | CONTINUOUS，细线 |
| `JianZhuFill` | 建筑**填充**（新增） | 浅灰 `#EFEFEF` / 252 | SOLID / HATCH 填充 |
| `GanLu`/`GuanLang`/`PeiXianTu`/`ZhuangHao`/`BiaoQian`/`JuLi` | 业务层（**保持不变**） | 现有等级色 | **线宽可控、置顶** |

> 原则：底图用**浅色细线 + 填充**做"背景"，业务层用**深色/彩色 + 明确线宽**做"前景"，从颜色和线宽两个维度拉开主次。

**（2）道路分级制图（解决"路太粗/不粘连"）**
- **改为"双线描边 + 中心线"画法**：道路按宽度生成**两侧平行双线（casing）**，中间画**中心线**；不再用"实心宽带"。
- **分级配色/分级线宽**：主干道（motorway/trunk/primary）、次干道（secondary/tertiary）、支路（residential/unclassified）、小路（service）分别配不同描边线宽与中心线颜色，**至少 3 个可见等级**。
- **casing 线宽"瘦身"**：道路实际宽度**不再 1:1 直接当线宽**，改为**按等级映射的显示宽度**（如主干 1.0mm、次干 0.6mm、支路 0.35mm、小路 0.2mm 的等效图面宽度），保证相邻路**不粘连**。
- 复用现有 `_appendCorridor`（`dxf.dart:443-481`）的**偏移多段线**算法生成双线（该算法已处理转角对接，可直接借鉴）。

**（3）建筑填充 / 浅色处理（解决"没有轮廓感"）**
- 建筑**闭合轮廓保留**（现有）＋**新增整体填充**：R2000 用 **HATCH**，R12 回退用 **SOLID** 实体近似填充（见 3.4）。
- 建筑轮廓改**浅灰细线**、填充用**更浅灰**，使建筑成为"成片浅灰块"，与道路/空白三层分明。
- 复杂关系型建筑（N2）需先**规范化几何**（取外环 / 合并成员），避免畸形。

**（4）文字高度与注记规则**
- 地名：片区名 > 小区/村名，字号分级（建议 4.0 / 3.2）；沿地块中心落点，**可选旋转至地块长轴**。
- 道路名：维持"沿弧长重复 + 随等级字号"（现有 `dxf.dart:324-355` 可沿用），**随等级重新标定字号**。
- 建筑名：字号**不再硬编码 3.0**（N6），随比例尺/等级给足；仅对有 `name` 的建筑输出。
- **注记避让（P1）**：地名/路名/建筑名之间做**简单重叠检测**，重叠时移位或省略，避免叠字。

### 3.4 DXF 版本决策

> 用户可能要把图交给甲方/同事，**兼容性重要**。

| 方案 | 能力 | 兼容性 | 结论 |
|---|---|---|---|
| 仅 R12（现状 AC1009） | 无图层线宽(370)、无真彩(420)、无 LWPOLYLINE/MTEXT/HATCH | 极广（老 CAD 也能开） | **保留为选项**，不再作唯一 |
| **升级 R2000（AC1015）** | 支持**图层线宽 370 / 真彩 420 / LWPOLYLINE / MTEXT / HATCH** | AutoCAD 2000+ 与市面主流（AutoCAD、浩辰、中望、天正）**均支持** | **推荐设为默认**——这是"美观 + 线宽可控 + 建筑填充"的技术前提 |
| 双版本导出（用户选） | 兼顾 | 用户自行权衡 | **推荐实现**：默认 R2000，提供"兼容旧版 R12"勾选 |

**推荐**：**默认导出 R2000（AC1015），对话框提供"R12 兼容模式"开关**。
- 技术上：R2000 才能落地 §3.3 的**线宽分级**与**建筑填充**（R12 只能用 SOLID 勉强填、无法定义图层线宽）。
- 对用户的利弊讲清楚：R2000 图更专业美观、线宽可控；极老的 R12 专用读取器可能打不开（2026 年设计院场景罕见）。**R12 模式作为老软件兜底**保留。
- 注意：GBK（`ANSI_936`）写盘策略**两版本都保留**（`dxf.dart:53-54, 410`），中文不乱码。

### 3.5 性能与体量控制

| 手段 | 说明 | 优先级 |
|---|---|---|
| **网格简化** | 建筑/道路按精度分级简化（道路容差按等级调，如主干 0.5m、小路 2m；N4）；建筑可做**小面积且无名**轮廓合并 | P1 |
| **按图层开关** | 导出对话框支持**单独勾选**：道路 / 建筑填充 / 地名 / 建筑轮廓（替代现在"一个总开关全有全无"） | P0 |
| **只导出视野内** | 以**当前地图视野**或"线路 + 缓冲带"为准，避免超大面积 | P1 |
| **缓冲区宽度可调** | 外扩距离（现固定 0.008°，`dxf.dart:270`）**改为可配**（如 300m/500m/1km 档位） | P1 |
| **缓存复用** | 见 3.1 的 S3，避免重复下载与重复解析 | P0 |

## 4. 需求池

> 优先级：**P0＝本次必做（Must）**、P1＝应做（Should）、P2＝可做（Could）。
> 每项给用户故事 + 验收标准，可直接转架构设计 / QA 用例。

### P0（本次落地，5 项）

**P0-1　建筑轮廓"成片可辨"（填充 + 图层规范）**
- 用户故事：作为出图的人，我希望建筑是**成片的浅灰块**，这样在 CAD 里一眼能看出小区/街区的形状。
- 验收：对应验收项 **A1、A2**——建筑闭合轮廓保留 + **新增填充**；JianZhu 改浅灰；密集城区建筑连成可辨图块；缩小到自动比例仍可辨。
- 备注：几何需先规范化（N2）。

**P0-2　道路分级制图（双线 + 中心线，解决"路太粗/不粘连"）**
- 用户故事：作为出图的人，我希望道路**有等级、粗细分明、不糊在一起**，这样图面才像设计院的图。
- 验收：对应 **A3、A4**——道路改为**双线描边 + 中心线**；≥3 个等级；相邻路不粘连；主干道显著。
- 备注：显示线宽按等级映射，**不再用真实路宽 1:1**（`dxf.dart:313-315` 重写）；可复用 `_appendCorridor` 偏移算法。

**P0-3　小区 / 村庄 / 片区名抓取与注记**
- 用户故事：作为设计人员，我希望底图上有**小区名/村名**，这样写设计说明、判断现场时能对上地方。
- 验收：对应 **A5**——新增 Overpass `place=*` + `landuse=residential` 名称抓取；输出独立图层 `DiMing`；可选天地图 POI 兜底；字号可读、不乱码、少重叠。
- 备注：修复 N1（勿丢弃居住区内部无名路），使"小区"空间可辨。

**P0-4　底图数据源可靠性（多镜像 + 缓存复用 + 失败可见）**
- 用户故事：作为出图的人，我希望**第一次抓到之后就不再看网络脸色**，失败了也要**明明白白告诉我**。
- 验收：对应 **A9**——多镜像（含国内可达端点）竞速；**项目级底图缓存**，同区域重复导出**离线可复用**；抓取结果三态（全成功/部分/全失败），失败给**中文可操作指引**而非仅 toast。
- 备注：保留现有并行竞速（`overpass.dart:120-149`）；缓存键按**区域量化**而非仅查询串。

**P0-5　DXF 版本升级为 R2000（默认），保留 R12 选项**
- 用户故事：作为要交图的人，我希望图**在主流 CAD 里打开就是专业的样子、线宽可控**，同时老软件也能兜底。
- 验收：对应 **A6、A7、A10**——默认 `AC1015`，支持 **370 线宽 / 420 真彩 / LWPOLYLINE / HATCH**；对话框提供"R12 兼容"开关；两版本中文均不乱码。
- 备注：业务图层线宽可控（R12 下杆路 LINE 零线宽问题，`dxf.dart:125-126`，在 R2000 下用图层线宽或 LWPOLYLINE 常宽解决）。

> **说明**：P0-1~P0-4 与 P0-5 **互相依赖**——R2000 是"填充 + 线宽分级"的技术前提，建议**同一批次落地**，否则又变成"打补丁式改一半"（用户已因此不满数十次）。

### P1（应做）

- **P1-1　注记避让**：地名 / 路名 / 建筑名之间的简单重叠检测与移位（对应 A5、A8）。
- **P1-2　缓冲区与导出范围可调**：外扩距离档位（300m/500m/1km）、"仅导出当前视野"。
- **P1-3　底图图层细分开关**：道路 / 建筑填充 / 建筑轮廓 / 地名 **分别可勾选**，应对体积与观感取舍。
- **P1-4　体量控制**：按等级的网格简化 + 小面积无名建筑合并，控制大范围 DXF 体积。
- **P1-5　天地图地名兜底开关**：OSM 缺名时用天地图 POI 补充（含开关键、用量提示）。

### P2（可做）

- **P2-1　建筑名（楼栋名）注记**：对有 `name` 的建筑补注楼栋名，字号随比例尺。
- **P2-2　底图配色主题**：提供"黑白打印友好"配色（便于甲方黑白出图）。
- **P2-3　离线底图包**：按地区预打包，完全离线（依赖 P0-4 缓存模型）。
- **P2-4　导出预览**：导出前生成缩略预览，勾选即可见效果（减少"改了看不到结果"的反复）。
