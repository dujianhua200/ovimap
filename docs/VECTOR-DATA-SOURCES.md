# 矢量数据来源：能拿什么、拿不到什么（2026-09-27 核实）

> 目标：给线路设计用的 DXF 底图补更多矢量（建筑轮廓、道路、地名…）。
> 结论先说：**高德、天地图都不公开"建筑/道路中心线"这类矢量几何**。

## 一、官方开放能力对照

| 来源 | POI/地名点 | 行政区划轮廓 | 建筑轮廓 | 道路中心线 | 水系/铁路 |
|---|---|---|---|---|---|
| **OSM / Overpass**（现用） | ✅ | ✅ | ✅（县城稀疏） | ✅ | ✅ |
| **高德 Web 服务** | ✅（已接入） | ✅ `district` | ❌ 不开放 | ❌ 不开放 | ❌ |
| **天地图 Web 服务** | ✅（已接入） | ✅ `administrative`（`needPolygon:true`） | ⚠️ "居民地要素"需单独申请/购买 | ⚠️ "道路要素"同上 | ⚠️ "水系要素"同上 |
| 天地图**瓦片**（vec_w / cva_w） | — | — | 栅格 PNG，**不是矢量** | 栅格 | 栅格 |

- 天地图官方"数据 API"确实列了**政区/道路/水系/居民地要素**四类，但这几项不在免费开放列表里，
  需要在 lbs.tianditu.gov.cn 单独申请（部分需购买）。**免费且确定可用的是行政区划轮廓**。
- 高德/百度的矢量瓦片是**加密/混淆的内部格式**，抓取解码违反服务条款且随时失效——
  不作为产品方案（可玩，但别依赖）。

## 二、真正能把"矢量变多"的三条路

### A. 自建 Overpass 实例（推荐，数据最全、无配额）
- 下载区域 pbf：`https://download.geofabrik.de/asia/china.html`（中国 ~1GB；可只取河南省 ~200MB）
- 服务器：`docker run overpass` + `osmium` 提取 bbox 后导入；16GB 内存可跑省级，县级 4GB 够
- 收益：查询毫秒级、无公共镜像限流、可导入**自己的补测数据**（挑着补自己常做的乡镇）
- 你有自建服务器（hzyt 反代），这条路成本最低、效果最好

### B. 本地矢量包（离线、最稳）
- pbf → GeoJSON：`osmium export` 或 `osm2pgsql + ogr2ogr`，按 bbox 导出建筑/道路/水系
- 在 App 里「导入底图 GeoJSON」即可离线出图（已支持，18MB 整市样本实测可用）

### C. 应用内多抓要素类型（已做）
- v3.9.4 起新增 **电力线 / 水系沟渠** 一路查询（OSM 覆盖远好于建筑）
- 后续可扩展：铁路、围墙/栅栏（barrier）、沟渠（waterway=drain）、沟、高压塔（power=tower）

## 三、为什么现在感觉"少"
1. 县城/乡镇的 OSM **建筑轮廓**本身稀缺（不是我们漏查：查询已经是 `way[building]` + `relation[building]` 全量）
2. 沿线路缓冲裁剪（v3.9.3）会把远离轨迹的要素裁掉——这是刻意的，范围可调
3. 公共 Overpass 镜像常限流/超时 → 建议走 A 或 B
