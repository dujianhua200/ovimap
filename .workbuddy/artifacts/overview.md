# 滑洲云图 · 第十六批交付总览

> 主题：**"导出的 DXF 经常打不开、没有建筑轮廓"根因修复**。
> 用户当场质疑：「难道没有开源的矢量数据可以使用吗，**你自己就不能查看一下导出的是什么样子能不能使用**」——这次先自己把文件生成出来、用真实 DXF 解析器打开看，再动手。

## 一、根因（用实物验证，不是靠测试判绿）

我把真实导出的文件用成熟解析库 **ezdxf** 严格校验：

| 文件 | 严格打开 | 容错打开 |
|---|---|---|
| **R2000（上一版默认）** | ❌ 失败 `IndexError` | ❌ **也失败** |
| R12 | ✅ 成功（AC1009） | — |

**坏因**：R2000 文件缺了 R2000 必需结构——没有 `$HANDSEED`、**实体没有句柄**、**没有 OBJECTS 段**、**没有 `100 AcDb*` 子类标记**。等于**给 R12 结构的文件贴了张 R2000 标签**，文件非法 → 不同 CAD 容错不同 → "碰运气能打开"。

**"没有建筑轮廓"的真相**：同一底图导出成 R12，按图层拆开数——`JianZhu`（建筑轮廓）/`JianZhuFill`（填充）/`DiMing`（地名）/`DaoLuBian`+`DaoLuZhong`（道路分级）**全都在**。**渲染逻辑本来是对的**，是被坏文件连累：**CAD 强行打开非法文件时会静默丢弃解析不了的实体**（首当其冲就是建筑填充）。底图数据源实测也是通的（`overpass-api.de` 200/1.3s、`kumi.systems` 200/2.3s）。

## 二、修复

1. **默认导出改回 R12**（已证明可打开）——你不改设置时拿到的一定是能打开的文件
2. **R2000 没有下线，而是补齐了合法结构**（完整 HEADER + `$HANDSEED` + CLASSES 段 + 记录句柄 + 每个实体句柄 + `100 AcDb*` 子类标记 + OBJECTS 段），保留为**手动可选**并加提示"老 CAD 可能提示修复，不确定就用 R12"
3. **双闸门防复发（本批最重要的沉淀）**
   - **Dart 结构校验器**：**写盘前**强校验，不合法直接抛错拦截 → 不可能再产出半成品文件
   - **真实解析器闸门**：`tool/validate_dxf.py` 用 ezdxf 严格打开样本
   - ⚠️ QA 独立证明：**只靠 ezdxf 拦不住上一轮的 bug**（R12 结构贴 AC1015 标签时 ezdxf 会放行）——**真正拦住它的是 Dart 写盘前校验器**。两者互补，且**"文件里有没有某几个字"这种字符串断言已正式废掉，不再作为合法性依据**
4. **底图项目级近乎永久缓存**（原来 7 天过期）——抓一次长期复用，不再每次赌网络
5. **新增本地开源矢量底图导入**（GeoJSON：Polygon=建筑 / LineString=道路 / Point=地名，零新依赖）——**这就是"用开源矢量数据"的落点**：你可自行下载 OSM/GeoJSON 导入，**完全离线也能出带建筑的图**
6. **成册改回 R12**：成册是交给结算/甲方的资料，兼容性优先
7. 修 GeoJSON 坐标异常的报错类型（契约一致，不静默产脏数据）

## 五、请在 CAD 里逐条验收

1. **能打开**：双击任一导出 `.dxf`（默认 R12）→ **能开且不弹"recover/修复"**。请用"打开"，不要用"导入/恢复"
2. **看图层**：命令行 `LAYER` → 应有 `JianZhu`(建筑轮廓)、`JianZhuFill`(填充)、`DiMing`(地名)、`DaoLuBian`/`DaoLuZhong`(道路)
3. **看小区**：放大到小区位置 → **闭合的建筑轮廓多边形**（带孔建筑有内环）+ 填充色块；`DiMing` 层可见**地名/小区名文字**
4. **业务层置顶**：选中一根杆路，确认 `GanLu`/`PeiXianTu`/`ZhuangHao` **压在底图之上**，不被道路/填充盖住
5. **中文不乱码**（GBK/ANSI_936）
6. 若要试 R2000：请在目标 CAD 上确认同样能开、实体不丢

**只能用真机确认的**：AutoCAD / 中望 / 浩辰 对 R2000"最小表集"是否提示修复；R2000 的 HATCH 填充显示。**ezdxf 能开 ≠ 所有 CAD 都零提示**，这点必须你真机闭环。
