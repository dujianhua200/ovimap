### v3.9.0 收藏夹按奥维截图定版（用户第三次表达同一诉求 + 截图）
- **关键教训（写死在契约文档）**：用户三次要「所有东西都在收藏夹下可见 + 批量选择/删除」，我前两轮都在做折中（树只放文件夹或只放标记点、批量入口只在选中时出现且要按 Ctrl）→ 用户感觉"没做"。**功能的可发现性 = 功能本身**：批量能力必须是**常驻可见按钮**。
- 定版实现：① 树 = 唯一视图（根→文件夹→工程→标记点，depth*16 缩进，删掉下方列表这一重复渲染）；② 新增 `_selectBar` 工具条：全选/取消/导出所选/删除所选(N)/新建文件夹；③ 右键菜单顶部「删除所选 N 项」+ Ctrl+A / Delete 快捷键；④ 三类条目统一可选中（单击=选中+主行为、Ctrl 多选、Shift 范围选 `_selectRangeTo` 基于 `_visibleKeys()`）；⑤ 文件夹单击即展开。
- 实现要点：`_visibleKeys()`（树的可⻅行顺序，全选与范围选共用）、`_selected`（三类 id 混存）、`_deleteSelected`（三类混合一次确认）。

### 产物下载的稳定通道（运维经验，重要）
`gh release download` 在沙箱代理下对大文件经常**静默截断或 SIGTERM(137)**（APK 只下到 17MB、zip 2.5MB 就"成功"退出，sha256 不匹配）。
**可靠做法**（v3.9.0 实测一次成功）：
```bash
AID=$(gh api repos/dujianhua200/ovimap/releases/tags/<tag> --jq '.assets[] | select(.name|test("<pat>")) | .id')
gh api "repos/dujianhua200/ovimap/releases/assets/$AID" -H 'Accept: application/octet-stream' > dist/<file>
shasum -a 256 dist/<file>   # 与 gh api --jq '.assets[].digest' 比对
```
要点：**下完必须比对 size 与 sha256**，截断的文件也会"成功"写出。
