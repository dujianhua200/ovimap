# 2026-09-09 第十批：三个真机问题修复

## ① 普通模式点杆没反应（真 Bug，本轮最重要）
- 根因：命中检测用 TapPosition.relative 屏幕像素与 latLngToScreenOffset 对比——屏幕坐标换算受旋转/安全区/DPR/相对基准影响，真机上错位导致 30px 内全 miss（编辑模式长按续画、拓扑连线同一套逻辑，同样受害）。
- 修复：新增 `_hitTestGeo`（地理近邻法）——点击经纬度与各点直接 haversine，容差 = 35px×metersPerPixel（clamp 3~50m），与屏幕换算彻底解耦；view 点击/长按、edit 长按续画、topo 点击全部换用；删掉 _tapOffset/_hitTest/_hitTestDraft/_hitTestTopo。
- 教训：屏幕空间命中法在地图 App 里天生脆弱，地理空间近邻才是正道。

# 2026-09-09 第十二批：搜索提速精准 + 罗盘/定位箭头修复 + 普通模式点选已存收藏

## ① 搜索太慢/不精确（用户："不如奥维的搜索"）
- 根因：Nominatim/Photon 都是境外服务，国内不可达或极慢。
- 修复：SearchService 新增 `_tianditu` POI 关键字搜索作为**首选源**（`api.tianditu.gov.cn/search?postStr={keyWord,level:12,queryType:1,start:0,count:10}&type=query&tk=<key>`，UTF-8 解码 bodyBytes，返回 lonlat/x,y 取坐标，CGCS2000≈WGS84 直接 toDisplay）；有 key 优先、空结果或失败再回退 Nominatim→Photon。
- 关键：天地图 key 复用已配置的 `st.tiandituKey`（新增 getter，读 prefTdtKey），无需用户再填。SearchResult 改 name+address 双字段，结果弹窗名称加粗+地址灰字。未配 key 时提示走境外慢源、引导去「更多→天地图 Key 设置」。
- 教训：国内 App 搜索必须走国内源（天地图/高德/百度），境外 OSM 服务是网速坑。

## ② 罗盘/定位箭头方向 + 指北针回正
- 罗盘蓝楔方向 bug：原来 `heading - (compassMode ? mapRotation : 0)`，地图旋转时蓝楔与红针、与地图箭头口径不一致 → 改成**恒为 `heading - mapRotation`**（真北在屏幕 -mapRotation 处，手机航向 heading，屏幕角 = heading - mapRotation）。
- 航向滞后：`_smoothBearing` 系数 0.35 → 0.55，转动机身更快跟上。
- 指北针有时不回正：onTap/onLongPress 统一走 `_resetNorth()`——先 `_mapRotation = 0` + setState（红针立即回正），再 `_mc.moveAndRotate(center, zoom, 0)` 转相机，消除"缓存角没及时更新导致视觉没回正"。

## ③ 普通模式点选编辑只命中草稿的缺口（真缺口）
- 原来 view 模式 `_hitTestGeo(st.labels)` 只查草稿；保存后 labels 清空、已存工程在 overlayLabels（visibleCids）里，点不到。
- 修复：新增 `_hitTestAny` 返回 `(MapLabel, String)?` 记录（$1=label, $2=来源收藏id 空串=草稿），先草稿后可见收藏；view 点击/长按换用。
