### ⚠️ 缺陷一：AOT 把整棵 UI 裁掉（严重，交付前拦下）
- 现象：APK 从 65MB→47MB，`libapp.so` 9,438,088→4,457,352，**界面文字全部消失**、装上去卡"启动中…"
- 根因：`home_page._buildMarkers` 里 `buildBusinessMarkers(st, _mc.camera, …)` —— `flutter_map` 的 `MapController.camera` getter 在**首帧渲染前恒抛异常**（`value.camera ?? throw`），TFA 判其"必抛"→ 整棵 `build()` 返回链不可达 → 被裁
- **修正后的判据（工程师+QA 共同确认，行为学判据无官方文档）**：裁剪 ⟺ (a) 必抛调用位于**无条件**参与 `build()` 返回值的表达式链上 **且** (b) TFA 能证明接收者 `value.camera == null`（可追溯到裸 `MapController()` 构造）。三样本均自洽。
- **工程安全规则（长期，已固化为闸门）**：**`build()` 返回路径上绝不无条件读取「未就绪即抛异常」型 getter**（`?? throw` 模式），一律改用回调捕获的可空快照（`_cam?.x ?? 兜底`）。
- 排查手法（可复用）：`flutter clean` 重建 + `unzip -p` 取 libapp.so + UTF-16LE 检索中文 UI 串（对照包比较）+ ELF 节区对比排除 strip + 哨兵串二分。
