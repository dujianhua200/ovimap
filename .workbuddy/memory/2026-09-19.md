### 关键排障（两次红都不是功能缺陷，但都是真问题）
1. **`android-actions/setup-android@v3` 必挂**：它内部执行 `sdkmanager tools`，新版 sdkmanager 已移除 `tools` 包 → `Failed to find package 'tools'` → action 抛错，后续全部 skipped（看起来像 Android 完全跑不起来）。
   → **runner 本身就预装 Android SDK**（`/usr/local/lib/android/sdk`，cmdline-tools 16.0），该 action 多余。
   → 改为自己定位 SDK（ANDROID_HOME/SDK_ROOT/默认路径三重兜底）→ `--licenses` → 显式装
   `platform-tools` + `platforms;android-36` + `build-tools;36.0.0` + `ndk;28.2.13676358`（版本取自 Flutter 3.47.2 的 `FlutterExtension.kt`，与本机已装组件核对一致）→ 把 `ANDROID_HOME` 写回 `$GITHUB_ENV` 供后续步骤（含 apksigner 定位）用。
2. **`flutter test` 用例全绿却 exit 1（偶发）**：ubuntu 门禁第一次红（汇总 `501 passed / 2 skipped`、日志零报错），**同一提交重跑即绿（505/2）** → 定性为 flutter_tester 收尾崩溃偶发（macOS 上此前也见过 `TestDeviceException(segmentation fault)`）。
   → 对策：测试步骤做「**至多一次**重试」（首次非零退出再跑一次，两次都红才失败）。**不用 `|| true`**，不掩盖确定性失败。

### Android 签名（覆盖安装的硬需求）
- 原 `android/app/build.gradle.kts` 写死本机绝对路径 `/Users/dujianhua200/Doubao/滑洲云图/outputs/ManualApp/debug.keystore` → CI 上必然失败。
- 改为**三级解析**：`android/key.properties`（CI 由 Secret 还原，`storeFile` 用 `rootProject.file` 解析）→ 本机 legacy 绝对路径 → 都不存在时**不创建 ovimap**、回退 AGP 内置 `debug` 签名（实测配置阶段 exit 0，非死代码）。缺字段报中文错而非 NPE。
- 仓库已配 4 个 Secret：`ANDROID_KEYSTORE_BASE64`（`openssl base64 -A` 单行）/`ANDROID_KEYSTORE_PASSWORD`/`ANDROID_KEY_ALIAS`/`ANDROID_KEY_PASSWORD`（后三者值 `android`/`androiddebugkey`/`android`）。
- **新增签名一致性校验步骤**（质检 H1）：比对注入 keystore 的 SHA1 与 APK 实际签名 SHA1（用 `apksigner verify --print-certs`，**不用** `keytool -printcert -jarfile`，后者只看 v1 签名会误判）；`KS_B64` 为空直接 `::error` + exit 1。
- 实证：keystore SHA1 = `dfc826bb88e0426eda78750d0ab85cf300ee41c3`；CI 产物与**本机旧构建 APK 的 SHA1 完全一致** → 手机可直接覆盖安装，不用卸载（卸载会丢现场数据）。
