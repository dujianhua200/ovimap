### 本地环境踩坑（重要，下次直接用）
1. **本机 shell 有 HTTP 代理** `HTTP_PROXY/HTTPS_PROXY=127.0.0.1:56315`，会把
   `flutter_tester` 与测试进程之间的 localhost WebSocket 当外网劫持 →
   全部用例报 `Invalid WebSocket upgrade request`、`+0 -63` 全红。
   解决：跑 flutter 命令前 `export NO_PROXY="127.0.0.1,localhost,::1"`（小写也要设）。
2. **该 56315 代理连不上 github.com**（502 Bad Gateway），而**本机 10808 端口有可用代理**
   （v2ray 类客户端），经它访问 github.com / api.github.com 均 200。
   `gh` / `git push` 一律加 `HTTPS_PROXY=http://127.0.0.1:10808` 前缀。
   `api.github.com` 直连也通，但 `github.com` 直连超时。
3. `flutter analyze` **默认把 info 级 lint 也判为致命**（本项目有 68 条 info）→
   CI 门禁必须用 `flutter analyze --no-fatal-infos`，否则一推就红。
4. `gh auth login` 默认 scope 是 `gist, read:org, repo`，**没有 `workflow`**。
   推 `.github/workflows/` 下的文件会被 GitHub 拒绝，需
   `gh auth refresh -h github.com -s workflow` 补权限。
5. macOS `.app` 打包必须用 `ditto -c -k --sequesterRsrc --keepParent`，
   用 `zip` 会丢符号链接导致解压后打不开。
6. Windows runner 上写 `$GITHUB_ENV` 要用 pwsh + `Out-File -Append -Encoding utf8`，
   别用 Git Bash 重定向。

### 本机环境新踩坑（已写进技能，下次直接用）
- **小写代理变量优先级**：环境里 `http_proxy/https_proxy/HTTP_PROXY/HTTPS_PROXY` 四种都在，
  值都是坏的 56315。只前缀大写 `HTTPS_PROXY=...10808` 时 **git 仍走小写的 56315** →
  `CONNECT tunnel failed, response 502`。而同时刻 `curl -x 10808` 和 `gh` 全正常，
  极易误判为「网络没问题但 git 不通」（gh 只读大写变量）。
  解法：四种变量全覆盖，或 `env ... git push`。偶发
  `Error in the HTTP2 framing layer` 加 `-c http.version=HTTP/1.1` 重试。
- **私有仓库的 Release 资产直链返回 404（不是 403）** —— 未鉴权 curl 会被误判为
  「资产没传上去」。核验用 `gh release view <tag> --json assets` 取 `digest` 与本地
  `shasum -a 256` 比对，比真下载 35MB 更快更硬（本轮两边完全一致）。
- `gh release create` 会在远端**创建同名标签**，标签推送**不受 `paths-ignore` 约束**
  → 即使提交只改了 .md，也会再触发一次双平台 CI。
- 技能 `flutter-github-desktop-ci` 已同步更新：§6 要点表加 permissions 行、
